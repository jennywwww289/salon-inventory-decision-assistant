# 步驟二十二｜第二輪：文字層級

## 一、主要目標
### 動作
依步驟20的文字設計研究，統一首頁與庫存系統的標題、內文、標籤、輔助文字及數字樣式。
### 目的
改善標題與內文差異不足、小字難讀、重要數據不突出等問題，完成第二輪獨立美化。

## 二、輸入
### 動作
讀取：
- 設計原則研究文件中「文字層級」的內容與來源。
- docs/initial-self-evaluation.md。
- 步驟21最終修改紀錄。
- docs/screenshots/round-1-layout/README.md與最終有效截圖。
- 首頁、共用標題、工具列、庫存清單、代表性表單及彈窗的實際程式與樣式。

### 目的
從步驟21完成後的版本繼續修改，保留已改善的響應式配置。

## 三、本輪範圍
### 動作
只調整：
- 字級、字重、行高。
- 文字角色與標題語意。
- 數字對齊及必要的文字換行。
- 字級調整直接造成的局部溢位。

### 限制
- 不重做側欄、工具列與頁面配置。
- 配色、圓角、陰影不在本輪全面改版。
- hover、transition及互動狀態統一留到步驟23。
- 保留真實個人資料、技能程度、作品說明、Email及示範標示。
- 不修改庫存、交易、採購、統計、驗證、保存及通知規則。
- 不新增字型下載、UI框架或大型設計系統。
- 保留既有變更、初版截圖及兩個基準標籤。
- 不讀取或輸出憑證內容。

## 四、任務
### 任務1：保存本輪起點
動作：
- 記錄開始版本及現有未提交變更。
- 庫存畫面的修改前證據，引用步驟21最終有效截圖，不使用已判定不合格的舊桌機截圖。
- 首頁若步驟21未修改，可沿用初版截圖並註明。
- 修改前證據不足時，優先使用現有瀏覽器工具補拍；工具不可用則記錄版本與缺口，不偽造圖片。

目的：
讓本輪前後比較能歸因於文字層級修改。

### 任務2：建立少量一致的文字角色
動作：
先檢查現況，再直接採用一組簡單規則，記錄：
文字角色／字級／字重／行高／使用位置。

至少涵蓋：
1. 頁面標題。
2. 區塊標題。
3. 一般內文。
4. 表單標籤、表格文字與輔助說明。
5. 關鍵統計數字與狀態文字。

可用以下作為起點，依實際畫面調整並記錄最終值：
- 頁面標題約28～32px。
- 區塊標題約20～24px。
- 一般內文以16px為基準。
- 表格、標籤及輔助文字以14px為起點。
- 內文行高約1.5～1.7，標題行高約1.2～1.35。

上述是本專案設計選擇，不宣稱為官方強制規格。
首頁主視覺標題可有合理例外，但同角色在各頁應一致。

沿用現有Tailwind、CSS或共用類別管理方式。
避免用過度廣泛的全域選擇器，意外改壞圖表、圖示或第三方元件。

目的：
讓使用者能快速辨認標題、內容與次要資訊，並降低後續維護成本。

### 任務3：套用到代表畫面與共用元件
動作：
A. 個人首頁
- 強化姓名／主標題、區塊標題、作品名稱與內文的層級。
- 改善作品長段落、技能說明及聯絡資訊的閱讀。
- 維持合理的h1、h2、h3階層，不為了字體大小亂改標籤。

B. 庫存系統
- 統一各頁標題與共用表單、彈窗的文字角色。
- 庫存表頭、商品資訊、狀態、數量與金額清楚可辨。
- 數量與金額可採等寬數字及一致對齊，但不改變數值、單位或計算。
- 錯誤、保存失敗及示範限制說明保持清楚可讀。

C. 窄版處理
- 重要數字、錯誤訊息與操作文字不因新字級被裁切。
- 長文字可換行，或保留可到達完整內容的方式。
- 保留第一輪表格容器捲動及手機導覽配置。
- 不用縮小整頁、隱藏資訊或重新壓窄欄位來容納文字。

目的：
讓研究原則實際改善閱讀，同時保留第一輪成果與原有功能。

### 任務4：保存第二輪證據
動作：
- 保存完整Prompt，沿用現有對話紀錄方式。
- 記錄問題、對應研究原則、修改檔案、原因及驗收結果。
- 修改後截圖存入docs/screenshots/round-2-typography/。
- 首頁與庫存清單各至少一張代表畫面，整體涵蓋桌機與手機。
- 優先選兩張能呈現差異的畫面，不重拍無關頁面。
- 每張均對應相同頁面狀態、資料與拍攝條件的修改前證據。
- 沿用既有尺寸：桌機1440×900、平板820×1180、手機390×844。
- 記錄viewport與實際圖片尺寸，不縮放或覆寫原始證據。
- 更新截圖README與開發紀錄，記錄本輪版本。

目的：
留下可用於作業的第二輪前後比較與修改理由。

## 六、驗收與回報
### 程式檢查
- npm run lint及npm run build各執行一次。
- 若只有文字、語意標籤與樣式變更，不必重跑整套核心測試。
- 若碰到事件或共用行為，才執行相關既有回歸測試。
- 不新增只比對CSS類別或固定字級數值的測試。

### 畫面檢查
瀏覽器工具可用時：
- 檢查首頁與庫存清單在三尺寸下的標題、內文、表格與重要數據。
- 檢查一個代表性彈窗，確認文字及按鈕沒有因字級變更而裁切。
- 確認第一輪導覽、表格捲動及主要觸控區域未被縮小。
- 檢查本輪新增的Console錯誤。
- 其他尺寸通過檢查即可，不必全部另存截圖。

若工具仍不可用：
- 如實標示畫面與尺寸待驗證。
- 不安裝大型測試框架，不反覆嘗試相同失敗工具。
- 最後只列一次必要的代表畫面補證清單，使用「點哪裡／輸入什麼／預期看見什麼」。
- 不要求重做庫存、領料、採購與重新整理等完整真人流程。

### 回報格式
以表格列出：
測試目的／測試輸入／預期輸出／實際輸出／問題與通過判定。

另外精簡列出：
- 採用的文字角色規格。
- 修改位置、主要差異及原因。
- 前後截圖與版本位置。
- 已完成的實作、實際驗證結果及缺口。

保留步驟21尚未獨立實測的Console與44px尺寸缺口；本輪有實測才更新狀態。
不將型別檢查或建置成功當作畫面驗收通過。

完成後停止於步驟22，不進入步驟23。
