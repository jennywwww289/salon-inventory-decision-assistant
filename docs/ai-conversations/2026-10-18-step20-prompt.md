# 步驟二十｜研究至少三項設計原則

## 一、主要目標
### 動作
整理「Grid／Flexbox 排版」「文字層級」「微互動與狀態回饋」三項設計原則，對照目前專案，建立後續美化依據。
### 目的
讓步驟21～23各有明確問題、來源、修改方向與驗收方式，並留下作業需要的研究紀錄。

## 二、輸入
### 專案資料
讀取：
- docs/initial-self-evaluation.md
- docs/screenshots/before/README.md 與既有六張初版截圖
- docs/development-log.md 的相關紀錄
- 現有首頁、側欄、頂部工具列、庫存清單與代表性彈窗程式

依實際檔案定位元件，不假設檔名或路徑。重點確認窄版導覽與工具列、表格可讀性、文字層級。

### 官方研究來源
1. MDN：Grid 與其他排版方法的關係
https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Relationship_with_other_layout_methods

2. USWDS：Using type
https://designsystem.digital.gov/design-tokens/typesetting/overview/

3. USWDS：Button
https://designsystem.digital.gov/components/button/

補充來源：

https://www.w3.org/WAI/WCAG22/Understanding/reflow.html

https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html

6. MDN：prefers-reduced-motion
https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion

能連網時閱讀相關段落即可，不需廣泛搜尋。無法讀取的來源如實標示，不宣稱已閱讀。

## 三、本輪範圍
### 動作
本輪只研究、檢查與撰寫文件，網站程式僅供閱讀。
### 目的
保持三輪美化各自獨立，方便留下前後比較證據。

保留既有程式、示範資料、截圖及兩個基準標籤：
- original-baseline
- pre-beautification-v1

本輪不執行步驟21～24，也不新增套件。不讀取或輸出憑證內容。

## 四、任務
### 任務1：整理三項原則
每項以自己的話簡述：
- 原則重點及適用情境
- 來源標題、發布單位、完整連結、實際查閱日期及相關章節
- 對目前網站的用途

明確區分「來源提出的原則」與「本專案自行採用的規格」。
例如主要觸控目標至少44×44 CSS px，是本專案的驗收目標，不概括宣稱為所有WCAG AA情境的要求。

### 任務2：建立問題與應用對照
依初版自評、截圖及實際程式，製作表格：
問題／證據位置／相關檔案與元件／設計原則／預定步驟／修改方向／驗收方式。

可確認的問題才寫成既有缺點；僅由程式推測、尚未操作的情況，標示待驗證。

規劃方向如下，這輪只記錄：

A. 步驟21「第一輪：排版」
- 檢視固定側欄、頂部工具列、搜尋篩選、卡片、表格及彈窗。
- 規劃窄版導覽與工具列重排，主要操作目標至少44×44 CSS px。
- 表格保留可讀欄寬，必要時於表格容器內橫向捲動。
- 一般內容不因側欄或工具列被擠出畫面；彈窗內容與按鈕可捲動到達。
- 不以全頁裁切掩蓋版面問題。

B. 步驟22「第二輪：文字層級」
- 規劃頁面標題、區塊標題、內文、標籤、輔助文字與數字的字級、字重及行高。
- 沿用目前字型與技術，提出少量一致規則。
- 提升重要數據、狀態及錯誤說明的辨識度，不改寫真實個人資料與業務數值。

C. 步驟23「第三輪：互動回饋」
- 規劃hover、鍵盤focus、按下、停用、成功與錯誤狀態。
- 僅真實非同步等待顯示載入狀態，不增加人工延遲。
- 保留複製Email的成功／失敗判斷與aria-live回饋。
- 規劃適度transition及prefers-reduced-motion處理。
- 不改變庫存、帳本、採購、資料保存及示範功能的既有規則。

步驟24只記錄為視需要追加的配色、圓角、邊框或陰影整理，不預先認定必須執行。

### 任務3：規劃後續證據
為步驟21～23各列：
- 本輪唯一主要問題
- 預計修改位置與原因
- 修改前後需比較的代表畫面
- 驗收條件

沿用初版截圖清單記載的資料、尺寸與拍攝條件；保留原始圖片及既有尺寸差異紀錄。
每輪需留下Prompt、修改原因、版本與前後截圖。尚未產生的證據標示待完成。
