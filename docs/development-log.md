### 實際狀態規則

| 目前狀態 | 合法目標 | 副作用 |
|---|---|---|
| Draft 草稿 | Approved 核准；Cancelled 取消 | 不增加實際庫存或交易 |
| Approved 已核准 | Ordered 下單；Cancelled 取消 | 下單增加在途量，實際庫存／帳本不變 |
| Ordered 已下單 | Received 驗收；Cancelled 取消 | 驗收整單入庫並建帳；取消只扣回該單在途量 |
| Received 已驗收 | 無 | 重複驗收明確拒絕，不能回退或取消 |
| Cancelled 已取消 | 無 | 不能驗收或重新推進 |

- POStatus 原已包含 Cancelled；本輪將共用取消規則限於未驗收單據並處理在途量，未額外新增取消按鈕或採購編輯畫面。取消單據可在清單篩選查看。

### 共用檢查與一致更新

- validation.ts 的 validatePurchaseInput 在建立與推進時統一檢查供應商、非空品項、商品存在、product.supplierId 與單據供應商相符、正安全整數數量、非負有限單價及有限小計／總額。重複商品明確拒絕並指出商品，不默默覆寫；不新增 MOQ、售價或零元限制。

- 驗收逐不同品項沿用 applyInventoryMovement，使用最新商品庫存，不使用 po.items.currentStock。該核心改為保留傳入狀態的額外欄位，讓領料／退貨也保留同一份採購狀態，沒有建立另一套庫存算法。

### 庫存狀態採用的既有規則

按下列優先序，取原 recordTransaction 的 calculateStatus 門檻作唯一依據；不以種子註記或 UI 色彩建立另一套門檻：
1. stock ≤ 0，或 stock < reorderPoint 且週覆蓋 < 1.5：Critical。
2. 否則 stock ≤ reorderPoint，或週覆蓋 < 3：Low。
3. 否則週覆蓋 > 16：Overstock。
4. 其餘 Healthy。

零週需求的狀態沿用原本以 99 判斷的慣例（非零且高於補貨點時為 Overstock），沒有擅自另設業務門檻；但不再把 99 或除以 1 冒充實際覆蓋量，顯示「無需求，無法估算」。此零需求分類慣例尚未有額外業務定義確認，須保留為規則限制。門檻／需求更新、新增商品、異動及採購入庫都重算衍生狀態，不產生額外交易。
