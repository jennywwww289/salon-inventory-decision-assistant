# 綠境庫存｜沙龍門市決策與倉管小幫手

給沙龍與小型服務型店家用的庫存管理與補貨決策平台：看庫存狀態、記錄每次耗用、建立並追蹤採購單，並由「AI 決策建議」告訴店長該補什麼、為什麼。另附一個可進入系統的個人作品首頁。

> **目前狀態：展示原型。** 資料保存在使用者自己的瀏覽器（localStorage），尚未支援雲端或多人同步。「AI 決策建議」、LINE／Email 通知與角色切換仍是示範內容，**尚未串接**真實 AI、對外通知或登入權限。

## 版本說明

- **原始版本**：沙龍庫存網站（資料為內建範例，重新整理即重置）。
- **目前版本**：由 **Henry Yan** 以原始版本為基礎新增與補強，完整過程見 git 歷史與 [`docs/`](docs/)。
  - 個人作品首頁：自我介紹、技能、作品說明、聯絡方式，可進入庫存系統並返回首頁，內含複製 Email 功能。
  - 資料檢查：新增商品與表單會檢查必填欄位、重複 SKU、不合理數量與金額，並給具體錯誤提示。
  - 庫存與帳本連動：領料、採購入庫會更新庫存並留下交易紀錄；超過現有庫存的領料會被阻擋。
  - 採購流程：「草稿 → 核准 → 下單 → 驗收」狀態管理，避免跳步、重複入庫，以及供應商與商品不符。
  - 畫面與統計同步：庫存清單、商品明細、帳本與統計使用一致資料。
  - 本機資料保存：商品、交易、採購等資料重新整理後仍保留，並提供重設示範資料與保存失敗提示。
  - 介面改善：手機導覽、搜尋篩選、表格捲動、彈窗、文字層級，以及按鈕焦點、停用與成功／錯誤回饋。
- **公開版本的聯絡信箱**：為避免公開個人信箱，首頁、測試與文件裡的 Email 已換成佔位字 `your-email@example.com`。自行使用時請在 `src/components/home/PersonalHome.tsx` 改成自己的信箱，並同步更新 `tests/` 內對應的預期值。

## 功能

進入系統後，左側選單共 9 個頁面：

| 頁面 | 內容 |
|---|---|
| 總覽儀表板 | 今日營運決策摘要、庫存健康度與總庫存價值（進價）、需立即補貨清單、最新出入庫異動 |
| 庫存管理動態 | 各商品即時庫存動態表；可登記服務耗用、員工自用、零售帶走、破損報廢 |
| 商品品項清單 | 商品新增／編輯、SKU、成本、售價、補貨點、供應商；商品明細中可登記盤點校正與退貨 |
| 採購訂單與入庫 | 建立採購單（草稿 → 已核准 → 已下單 → 已驗收，各階段可取消），驗收後自動增加庫存並寫入帳本 |
| AI 決策建議 | 缺貨、積壓、需求預測、促銷四類建議；每則含原因、證據指標、預測與建議行動，可接受／修改／忽略並回饋（**靜態範例**） |
| 商業決策分析 | 依「發生了什麼事、為什麼、接下來可能怎樣、能採取什麼行動」四段呈現，另有未來 90 天展望與年度四季流速 |
| 品牌績效評估 | 各品牌營運績效與指標對照表，可新增合作品牌 |
| 供應商與促銷 | 供應商資料（MOQ、交期、付款條件）與促銷活動 |
| 人員角色權限 | 門市人員檔案與店主／店長／員工三種角色（**僅供顯示與記錄經手人，沒有實際權限限制**） |

庫存狀態分四級，由「現有庫存」「補貨點」「每週需求」計算（`src/utils/inventoryCalculations.ts` 的 `calculateInventoryStatus`）：

| 狀態 | 條件 |
|---|---|
| Critical（緊急） | 庫存 ≤ 0，或低於補貨點且可支撐不到 1.5 週 |
| Low（偏低） | 庫存 ≤ 補貨點，或可支撐不到 3 週 |
| Overstock（積壓） | 可支撐超過 16 週 |
| Healthy（健康） | 其他 |

## 快速開始

需要 Node.js 20.19 以上或 22.12 以上（Vite 8 的要求；開發時使用 Node 22）。

```bash
npm install
npm run dev
```

開啟 http://localhost:3000 。

| 指令 | 用途 |
|---|---|
| `npm run build` | 產生正式版到 `dist/` |
| `npm run preview` | 預覽正式版 |
| `npm run lint` | TypeScript 型別檢查（`tsc --noEmit`） |
| `node --import tsx --test tests/*.test.ts` | 執行全部測試（Node 內建 test runner） |

## 技術架構

- React 19 + TypeScript + Vite 8、Tailwind CSS 4、lucide-react 圖示
- 單一 React Context 管理狀態；業務規則放在 `src/utils/` 的純函式，不依賴 React，可直接單元測試
- 資料保存於瀏覽器 localStorage，沒有後端、沒有資料庫

```
src/
├── App.tsx                 # 首頁／系統兩區切換；系統內依 activeTab 切換頁面
├── context/AppContext.tsx  # 狀態、指令（記錄異動、建立採購單…）與本機保存
├── utils/                  # 驗證、庫存異動、採購單狀態機、庫存計算、本機資料
├── data/mockData.ts        # 範例資料（使用者、品牌、供應商、商品、帳本、採購單、AI 建議、通知）
├── types/index.ts          # 所有資料型別
└── components/             # 每個頁面一個資料夾（含 home/ 個人首頁），modals/ 放共用彈窗
tests/                      # node:test 測試
docs/                       # 開發日誌、測試報告、設計研究與前後對照截圖
```

## 環境變數

`.env.example` 列出 `GEMINI_API_KEY` 與 `APP_URL`，是從 Google AI Studio 匯出時帶來的範本。**目前程式碼沒有用到任何一個**，不設定也能正常執行。

## 已知限制

- 資料只存在使用者目前的瀏覽器，換瀏覽器或清除網站資料就會消失。
- AI 建議為靜態範例，未依實際庫存即時產生。
- 通知（LINE／Email）只會在畫面上產生一則紀錄，不會真的發送。
- 角色不影響任何功能權限。
- `package.json` 裡的 `@google/genai`、`express`、`dotenv`、`motion`、`autoprefixer` 目前沒有被程式碼引用。
